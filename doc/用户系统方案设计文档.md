## 3. 分阶段开发计划（按优先级）

> 每阶段 = 后端（TDD，先写测试）+ 前端实现 + 联调验收。
> 阶段 1-2 是所有后续阶段的地基；阶段 3 是本轮核心诉求。

### 阶段 1：后端数据基座 + 登录与鉴权

**后端**

- 新增依赖：`sqlalchemy>=2.0`、`pymysql`、`cryptography`、`PyJWT`
- MySQL 接入：`DATABASE_URL` 配置（`mysql+pymysql://user:password@127.0.0.1:3306/ai_quiz?charset=utf8mb4`），建库脚本 `ai_quiz`（utf8mb4）
- 数据表：`users`（id / openid / nickname / avatar / created_at / last_login_at）
- 登录接口：
  - `POST /api/v1/auth/login`：真实微信登录（code → code2Session → openid → 签发 token）
  - `POST /api/v1/auth/dev-login`：开发态模拟登录（仅 `DEBUG=true` 时开启，device_id 生成稳定 mock openid）
- 鉴权：PyJWT（HS256，30 天有效）；`Authorization: Bearer <token>`；鉴权依赖 `get_current_user`
- 错误码：`4003` 未登录/登录失效（HTTP 401）、`4004` 登录失败（HTTP 400）

**前端**

- 请求层注入 token；启动静默登录（`app.ts` 启动时）；H5 调试自动降级 dev-login（`Taro.login` 仅小程序端支持）
- 登录态存储（`Taro.setStorageSync('auth_token')`）；401 自动清理并重登一次

**验收标准**

- 后端 pytest 全绿（含登录、鉴权、mock 登录用例）
- 用 curl / Swagger 调 `/auth/dev-login` 可拿到 token，带 token 访问受保护接口正常
- 前端启动后 storage 中存在 token
- 真实微信登录代码就位（联调需测试号，不阻塞 mock 全流程）

### 阶段 2：用户信息 + 前端登录体验

**后端**

- `GET /api/v1/me`：返回用户基础资料与聚合数据
  - 基础：id / nickname / avatar
  - 统计：累计答题数 / 平均正确率 / 闯关数（阶段 3 后接入真实数据，先返回 0）
  - 续答：最近未完成闯关摘要（阶段 3 接入）

**前端**

- `userStore`（zustand）；个人中心页骨架 `pages/profile`（E01 基础版：昵称 + 工具箱入口 + 继续学习卡片占位）
- 首页右上「我」按钮从占位改为跳转个人中心

**验收标准**

- 打开小程序自动完成静默登录；个人中心显示默认昵称；接口 401 时自动重登

### 阶段 3：历史答题记录 + 续答（本轮核心）

**后端**

- 数据表：
  - `quizzes`：quiz_id / user_id / title / summary / source_type / questions(JSON) / status(doing/done) / current_index / created_at / updated_at / completed_at
  - `answers`：id / quiz_id / user_id / question_id / question_type / knowledge_point / selected_answers(JSON) / is_correct / duration_ms / created_at
  - `reports`：id / quiz_id / user_id / content(JSON) / created_at
- 接口：
  - `POST /quiz/generate` **改造为可选登录**：带 token → 题库入库并归属用户、状态 doing；不带 token → 保持原无状态行为（兼容现有测试与调试）
  - `PUT /quiz/{quiz_id}/progress`：幂等保存中途进度（current_index + 已答记录）
  - `POST /quiz/{quiz_id}/submit`：提交完整作答（records + 总用时），写入 answers、quiz 置 done
  - `GET /quiz/unfinished`：查询最近未完成闯关（供"继续"卡片）
  - `POST /report/generate` **改造**：带 token 时将报告落库（reports）

**前端**

- 闯关页 `quiz`：每答一题异步保存进度（失败不阻塞）；支持从已保存进度恢复（含已答记录）
- 首页 `index`：新增"上次没打完的"卡片（有未完成闯关时展示，"继续 →"跳转恢复）
- 报告页 `report`：生成成功后提交完成数据（替代/补充现有本地存档逻辑）

**验收标准**

- 答到一半退出 → 重进小程序，首页出现"上次没打完的" → 点击可恢复继续答题（题目、进度、已答记录一致）
- 完整通关后：quiz 状态为 done、answers 明细可查、报告落库
- 未登录（无 token）调用生成接口行为与现状一致

### 阶段 4：个人中心完整版 + 我的知识库（E02）

**后端**

- `GET /api/v1/me` 聚合真实统计（累计答题 / 平均正确率 / 闯关数 / 续答）
- `GET /api/v1/knowledge-base?status=all|doing|done`：历史闯关列表（标题 / 进度 / 正确率 / 状态 / 日期）

**前端**

- `pages/profile` 完整版（E01）：统计三宫格（去掉等级 / XP / 打卡区块，按暂缓决策）、工具箱（知识库 / 错题本[待确认] / 学习报表 / 设置[占位]）、继续学习卡片
- `pages/library`（E02）：全部 / 学习中 / 已完成筛选、进度条、正确率、"新"状态、空状态（E09-B 彩蛋）
- 「+ 学点新的」跳首页

**验收标准**

- 知识库列表数据与真实闯关记录一致；筛选切换正确；空状态按原型展示

### 阶段 5：学习报表（E03）+ 知识掌握详情（E04）

**后端**

- `GET /api/v1/me/stats?range=week|month|all`：正确率趋势（按天）、各领域掌握度
- `GET /api/v1/knowledge-base/{quiz_id}`：知识掌握详情（知识点清单：掌握 / 薄弱 / 未学）

**前端**

- `pages/stats`（E03）：趋势折线（CSS/View 手绘，贴原型）、领域掌握度条形图；**不做「本周打卡」区块**（打卡暂缓）
- `pages/mastery`（E04）：环形掌握度 + 知识点清单 + "再来一关，专练薄弱点"入口

**验收标准**

- 图表数据与真实答题记录一致；知识点归因使用题库中的 knowledge_point 字段

## 4. 技术方案

### 4.1 后端

| 项 | 方案 |
| --- | --- |
| 数据库 | MySQL 9.7（本机服务 `MySQL97`）：库 `ai_quiz`（utf8mb4）；测试库 `ai_quiz_test` |
| ORM | SQLAlchemy 2.0（同步引擎 + Session）；驱动 PyMySQL（纯 Python，Windows 无编译问题；MySQL 8+ 认证需 `cryptography`） |
| 配置项（.env） | `DATABASE_URL`、`JWT_SECRET`、`JWT_EXPIRE_DAYS`、`WECHAT_APPID`、`WECHAT_SECRET`、`AUTH_MOCK_ENABLED` |
| 鉴权 | PyJWT HS256；`Authorization: Bearer <token>`；`get_current_user` 依赖注入；未登录返回 4003 |
| 微信登录 | `code2Session`（服务端 http 调用）：`GET https://api.weixin.qq.com/sns/jscode2session?appid=..&secret=..&js_code=..&grant_type=authorization_code`，取 openid 建号；详细参数在开发登录模块前再次核对官方文档 |
| 可选登录设计 | `quiz/generate`、`report/generate` 保留匿名可用；其余新接口全部要求登录 |
| 错误码扩展 | 4003 未登录（401）、4004 登录失败（400）、4005 资源不存在（404） |

### 4.2 前端

| 项 | 方案 |
| --- | --- |
| 登录时序 | `app.ts` 启动 → `Taro.login()` 取 code → `POST /auth/login`；失败（H5 / 无测试号）→ `dev-login` 兜底（仅开发环境） |
| token 管理 | storage 持久化；请求层统一注入；401 清 token 重登一次后重试原请求 |
| 新增页面 | `profile`（E01）、`library`（E02）、`stats`（E03）、`mastery`（E04）、（待定：`wrongbook` / `redo`） |
| 页面改造 | `index`：我入口 + 上次没打完卡片；`quiz`：进度保存 / 恢复；`report`：通关数据上报 |
| UI 规范 | 严格对齐原型图（E01-E09）与设计系统板（色彩 / 字体 / 描边 / 硬阴影 / 8px 栅格 / 文案语气） |
| 图表实现 | 折线图：View/CSS 手绘（点 + 线段），确保小程序端兼容；环形图：conic-gradient（现有 report 已验证可用） |

### 4.3 TDD 与测试策略

- 后端所有新接口**先写测试再实现**，沿用现有测试模式（`TestClient` + 依赖覆盖 / Mock）
- 测试数据库：默认 **SQLite 内存库**（随时可跑、快、无副作用）；业务代码避免 MySQL 专属 SQL；另加 **MySQL 冒烟测试**（连 `ai_quiz_test`）验证真实库方言兼容
- 现有 70 个测试必须保持全绿（生成 / 报告接口的匿名行为向后兼容）

## 5. 微信登录接入路径（用户操作指引）

1. **获取 AppID + AppSecret**（二选一）：
   - 路径 A（推荐）：微信公众平台注册「小程序」个人主体（免费），在「开发管理 → 开发设置」获取 AppID 与 AppSecret；
   - 路径 B：微信开发者工具新建项目时选择「测试号」（能力有限，以微信官方当前指引为准）。
2. 将 AppID / AppSecret 填入 `backend/.env`，并将 `AUTH_MOCK_ENABLED` 置为 `false`，重启后端即切换真实登录（前端无需改动）。
3. 开发期在微信开发者工具勾选「不校验合法域名」（后端为 `http://127.0.0.1:8000`）。
4. 说明：当前 `project.config.json` 为 `touristappid`（游客模式），无法换取真实 openid；拿到测试号后替换 `appid` 字段。

## 6. 风险与注意事项

| 风险 | 应对 |
| --- | --- |
| MySQL 9.7 较新，驱动兼容 | 使用最新 PyMySQL + SQLAlchemy 2.x；先跑冒烟测试验证；必要时调整 |
| 本地 MySQL 密码 / 用户 | 由用户自行写入 `backend/.env`（不提交 git），文档与代码不接触明文密码 |
| H5 端 `Taro.login` 不可用 | H5 调试走 dev-login（仅开发配置开启） |
| 中途进度保存失败 | 异步保存不阻塞答题；下次全量覆盖（幂等） |
| 数据一致性 | 提交完成时以本次提交的 records 为准重算 answers，避免脏数据 |
| 时区 | 统一使用 `Asia/Shanghai`（服务器本地时间）记录日期时间 |
